# GhostLock-X200 v1.3.5-beta3 (最终 beta, 未公开发布)

## 与 v1.3.5-beta2 的差异

- **STAGE0 内核匹配门禁**: 设备内核 release 与机型偏移不匹配时, 在第一次内核写之前退出
  (防跨内核错偏移强跑 panic)。
- **STAGE4 前静默门**: 推包/反汇编负载消退后再执行 STAGE5 首轮写, 提高 R1 命中率;
  设备后台负载极高时 (loadavg>=20) **硬中止并提示关闭后台应用**,
  避免写链在极端负载下 panic (实测 loadavg=50 时 R1 即 panic; <=16 时 7/7 通过)。
- **vr.ko 对抗偏移跨机型化**: vr_offsets 优先读机型模块 `devices/<id>/vr_offsets.json`,
  回退 b57 默认, 缺失时内置默认并提示。
- **非 b57 机型 glt 门禁**: 非 b57 机型禁止静默使用 b57 编译的 prebuilt glt
  (编译期偏移跨内核必 panic); 必须使用本机型编译产物, 缺失时自动编译
  (WSL kali NDK, 无 NDK 时提示体积/路径后确认下载 Windows 版), 失败即终止。
- **w2host 轮询降负载**: 每轮额外 1ms 睡眠, 降低写链窗口期自干扰。
- **修复重跑 su 失效**: /data/adb 被 KernelSU 装成 0700 后, 二次运行的 shell
  无法穿越目录 -> su 全灭; ksetup 落位时强制 /data/adb=0755 (实证修复)。
- **诊断文案**: 明确要求发送诊断包 zip。

## 已知情况

- STAGE5 写链为概率性时序原语: 设备繁忙时首轮可能 miss (安全), 由后续轮次命中;
  一次运行内完成, 不重启不 panic。
- 写链在极端设备负载 (loadavg 很高、内存/IO 压力) 下有 panic 风险;
  静默门在 loadavg>=20 时中止运行 (重启设备后重试), 不冒险写入。
- 仅 X200 PD2415 (b57) 真机适配; 其他机型需自行生成模块并编译本机型 glt。
- 在线卸载内核模块 (rmmod) 会触发 kernel panic, 工具不提供在线卸载;
  如需清理模块, 重启设备即可。
